ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Модуль аэродинамического расчёта для военной симуляции
(ракеты, БПЛА, крылатые ракеты)

Версия: 1.0
Дата: 10 февраля 2026 г.


1. ОБЩИЕ ТРЕБОВАНИЯ
───────────────────────────────────────────────────────────────────────────
1.1. Назначение
    Модуль аэродинамического расчёта (IAeroCalculator) предназначен для
    вычисления аэродинамических сил и моментов в реальном времени для
    военных летательных аппаратов: управляемых ракет, БПЛА, крылатых ракет.

1.2. Требования к точности
    Максимальная ошибка расчёта коэффициентов сил/моментов относительно
    экспериментальных данных — не более 15% во всех режимах полёта
    (субзвук, трансзвук, сверхзвук до M=5.5).

1.3. Требования к производительности
    Максимальное время расчёта одного вызова — 150 мс на процессоре
    Intel i7-12700 (однопоточный режим). Достижение лимита 100 мс невозможно
    при учёте трения на всех поверхностях с сохранением точности ≤15%.

1.4. Система координат
    Связанная правая система координат ЛА:
      • Ось X — вперёд вдоль продольной оси фюзеляжа
      • Ось Y — вправо (по правому борту)
      • Ось Z — ВВЕРХ (критически важно для знаковых соглашений)
    Все силы и моменты вычисляются относительно центра масс в этой СК.

1.5. Архитектурные ограничения
    • Базовый класс: IAeroCalculator с виртуальным деструктором
    • Управление памятью: строго RAII, нулевые сырые указатели для владения
    • Владение геометрией: std::shared_ptr<const GeometrySTL>
    • Потокобезопасность: НЕ потокобезопасен. Требуется один экземпляр
      модуля на каждый летательный аппарат.
    • Внешние зависимости: только STL и Eigen. Запрещены Boost, CGAL,
      OpenFOAM, SU2 и другие внешние солверы.


2. ВХОДНЫЕ ДАННЫЕ
───────────────────────────────────────────────────────────────────────────
2.1. Условия полёта (структура FlightConditions)
    Входной интерфейс НЕ принимает углы атаки и скольжения напрямую.
    Вместо этого передаётся вектор скорости в СВЯЗАННОЙ СК ЛА:

      • velocity_body — вектор [u, v, w] в м/с в связанной СК
        (углы α и β вычисляются внутри модуля:
         α = atan2(w, u), β = arcsin(v / |V|))

      • mach — число Маха (диапазон 0.0 — 5.5)

      • density — плотность воздуха ρ [кг/м³] от внешней атмосферной модели

      • temperature — температура воздуха T [K]

      • dynamic_viscosity — динамическая вязкость μ [Па·с]
        (вычисляется внешней атмосферной моделью по закону Сазерленда)

      • angular_velocity — вектор угловых скоростей [p, q, r] в рад/с
        относительно осей связанной СК [X, Y, Z]

      • com — координаты центра масс в связанной СК [м]

      • altitude_agl — высота над уровнем земли [м] для коррекции
        эффекта земли

2.2. Геометрические данные
    Геометрия задаётся в формате STL (ASCII или бинарный), масштаб 1:1 в метрах.
    Каждый компонент ЛА — отдельный STL-файл:
      • Фюзеляж / корпус
      • Каждая несущая поверхность (крылья, оперение)
      • Каждая поверхность управления (рули направления/высоты/крена)

2.3. Метаданные в STL
    Референсные величины извлекаются ИСКЛЮЧИТЕЛЬНО из метаданных в комментарии
    STL-файла. Формат комментария (после ключевого слова 'solid'):

      solid component_name // AERO:S_ref=0.35,b_ref=1.2,c_ref=0.28,lambda=8.5,type=WING

    Обязательные поля:
      • S_ref — референсная площадь [м²] (обычно площадь крыла в плане)
      • b_ref — размах крыла [м] (для нормировки моментов крена/рыскания)
      • c_ref — средняя аэродинамическая хорда [м] (для нормировки момента тангажа)
      • lambda — удлинение крыла λ = b²/S (для моделирования срыва)
      • type — тип компонента: FUSELAGE, LIFTING_SURFACE, CONTROL_SURFACE

    При отсутствии ЛЮБОГО обязательного поля — выбрасывается исключение
    std::runtime_error с указанием отсутствующего параметра.

2.4. Поверхности управления
    Каждая поверхность управления задаётся структурой:
      • Имя поверхности (строка)
      • Умный указатель на геометрию STL поверхности
      • Угол отклонения [рад] в текущий момент
      • Ось шарнира в СВЯЗАННОЙ СК ЛА (единичный вектор)
      • Точка шарнира в СВЯЗАННОЙ СК ЛА [м]
      • Максимальный и минимальный углы отклонения (физические ограничения)

    Обработка отклонения: геометрия поверхности подвергается жёсткому
    повороту вокруг оси шарнира перед интеграцией аэродинамических сил.


3. ВАЛИДАЦИЯ ГЕОМЕТРИИ
───────────────────────────────────────────────────────────────────────────
3.1. Общие требования ко всем сеткам
    • Минимальное отношение сторон треугольника (aspect ratio) > 0.15
    • Минимальная площадь треугольника > 1e-8 м²
    • Нормали ВСЕХ треугольников должны быть направлены НАРУЖУ от центра масс
      (проверка: скалярное произведение нормали на вектор от ЦМ к центроиду
       треугольника должно быть > 0)

3.2. Тип-зависимая валидация
    • FUSELAGE (фюзеляж): требуется замкнутая водонепроницаемая сетка
      (проверка по характеристике Эйлера: V - E + F = 2)
    • LIFTING_SURFACE / CONTROL_SURFACE: допускаются открытые сетки
      (только обшивка без заполнения объёма)

3.3. Обнаружение самопересечений
    Алгоритм на основе иерархии ограничивающих объёмов (BVH) сложностью O(n log n).
    При обнаружении самопересечения — исключение с указанием номеров
    пересекающихся треугольников.

3.4. Обработка ошибок валидации
    При любом провале валидации — выбрасывается std::runtime_error
    с описательным сообщением, включая координаты проблемной области:
      "Ошибка валидации STL 'wing.stl': внутренняя нормаль у треугольника 142
       в точке (1.23, -0.45, 0.78)"


4. ФИЗИЧЕСКАЯ МОДЕЛЬ
───────────────────────────────────────────────────────────────────────────
4.1. Режимы течения и методы расчёта
    • Субзвуковой режим (M < 0.7):
        — Панельный метод с вихревыми кольцами и условием Кутты
        — Учёт сжимаемости по поправке Прандтля-Глауэрта: C = C₀ / √(1-M²)
        — Интеграция трения по ВСЕМ поверхностям с учётом числа Рейнольдса

    • Трансзвуковой режим (0.7 ≤ M ≤ 1.3):
        — Линейная интерполяция между суб- и сверхзвуковыми результатами:
          C = C_sub·(1.3-M)/0.6 + C_sup·(M-0.7)/0.6
        — Волновое сопротивление учитывается эмпирически (ошибка ≤12%)

    • Сверхзвуковой режим (M > 1.3):
        — Теория Ньютона для осесимметричных тел (фюзеляж)
        — Линейная теория Акерета для тонких несущих поверхностей
        — Метод ударных волн/расширений для поверхностей управления
          с отклонением >10°

4.2. Учёт вязкости и числа Рейнольдса
    Число Рейнольдса: Re = ρ·V·c_ref / μ
    Коэффициент трения для турбулентного пограничного слоя:
      Cf = 0.455 / (log₁₀(Re))²·⁵⁸
    Трение интегрируется по ВСЕМ поверхностям (фюзеляж, крылья, рули).
    Это требует ограничения разрешения сетки (см. п. 7.2).

4.3. Модель срыва потока
    Критический угол атаки зависит от удлинения крыла:
      α_crit [°] = 10 + 5·log₁₀(λ)
    При |α| > α_crit:
      Cz = Cz_макс·cos¹·⁸(α - α_crit)
      Включается флаг stalled = true в результатах расчёта

4.4. Интерференция компонентов
    Упрощённая модель на основе метода площадей Прандтля:
      • Коррекция подъёмной силы крыла из-за присутствия фюзеляжа:
        ΔCz = Cz·(1 + 0.2·(d_фюзеляжа / b_крыла)²)
      • Смещение центра давления фюзеляжа из-за влияния крыла
    Ошибка модели ≤12% при типовых конфигурациях.

4.5. Эффект земли
    Активируется при высоте над землёй < 2.0·b_ref:
      ΔCz = Cz·(1 + 0.3·exp(-2·h / b_ref))
    Коррекция подъёмной силы и момента тангажа.

4.6. Демпфирующие моменты
    Добавляются к статическим моментам:
      my_демпф = Cm_q·q·(c_ref / (2·V))
      mz_демпф = Cn_r·r·(b_ref / (2·V))
      mx_демпф = Cl_p·p·(b_ref / (2·V))
    При скорости |V| < 0.5 м/с демпфирующие моменты НЕ учитываются
    (физически не имеют смысла при малых скоростях).

4.7. Аэродинамический центр
    Положение АЦ зависит от числа Маха:
      • M < 1.2: 25% САХ от передней кромки
      • M > 2.0: 50% САХ от передней кромки
      • 1.2 ≤ M ≤ 2.0: линейная интерполяция между 25% и 50%


5. ВЫХОДНЫЕ ДАННЫЕ
───────────────────────────────────────────────────────────────────────────
Результат расчёта возвращается структурой AeroResult:

  • Коэффициенты сил:
      Cx — коэффициент лобового сопротивления (положительный = сила против оси X)
      Cy — коэффициент боковой силы (положительный = сила по оси Y)
      Cz — коэффициент подъёмной силы (положительный = сила по оси Z вверх)

  • Коэффициенты моментов относительно ЦМ:
      mx — момент крена относительно оси X
      my — момент тангажа относительно оси Y
      mz — момент рыскания относительно оси Z

  • Физические величины:
      dynamic_pressure — динамическое давление q = 0.5·ρ·V² [Па]
      reynolds_number — число Рейнольдса
      force_body — вектор аэродинамической силы [Н] в связанной СК
      moment_body — вектор аэродинамического момента [Н·м] относительно ЦМ

  • Диагностические флаги:
      stalled — признак срыва потока
      alpha_rad, beta_rad — вычисленные углы атаки и скольжения
      ground_effect_active — активен ли эффект земли


6. ОБРАБОТКА ГРАНИЧНЫХ УСЛОВИЙ
───────────────────────────────────────────────────────────────────────────
При следующих условиях модуль ВЫБРАСЫВАЕТ исключение std::runtime_error:

  • Плотность воздуха ρ ≤ 0.01 кг/м³ (вне атмосферы)
  • Модуль скорости |V| < 0.1 м/с (нулевая динамика)
  • |α| > 85° или |β| > 85° после вычисления из вектора скорости
  • Число Маха M > 5.5 (гиперзвуковой режим требует иной физики)
  • Отсутствие обязательных метаданных в любом STL-файле
  • Невалидная геометрия после прохождения валидации

Исключения используются вместо возврата флага валидности для обеспечения
отказоустойчивости военной симуляции — ошибка геометрии или условий полёта
должна немедленно остановить расчёт, а не привести к некорректной траектории.


7. ОГРАНИЧЕНИЯ И ТРЕБОВАНИЯ К РЕСУРСАМ
───────────────────────────────────────────────────────────────────────────
7.1. Ограничение времени расчёта
    Гарантированное время выполнения ≤150 мс на Intel i7-12700 для полной
    конфигурации ЛА (фюзеляж + 2 крыла + 4 руля) при соблюдении ограничений
    на разрешение сетки (п. 7.2).

7.2. Ограничение разрешения сетки (для соблюдения 150 мс с трением)
    • Фюзеляж: не более 2 500 треугольников
    • Несущая поверхность: не более 800 треугольников на поверхность
    • Поверхность управления: не более 200 треугольников на поверхность
    Превышение лимитов не гарантирует укладывание в 150 мс.

7.3. Кэширование геометрии
    Модуль имеет право кэшировать предвычисленные панельные сетки между
    вызовами calculate() для повышения производительности. Кэш реализуется
    через изменяемые (mutable) члены класса для сохранения логической
    константности метода calculate().

7.4. Потребление памяти
    Пиковое потребление памяти для полной конфигурации — не более 150 МБ
    (включая кэш панельных сеток и временные буферы).


8. ВЕРИФИКАЦИЯ И ТЕСТИРОВАНИЕ
───────────────────────────────────────────────────────────────────────────
8.1. Обязательные верификационные тесты
    Для подтверждения точности ≤15% должны быть пройдены тесты:

    Тест 1 — Сфера диаметром 0.1 м:
      Условия: M=0.3, Re=2·10⁵
      Ожидаемый Cx: 0.47 ± 0.07 (ошибка ≤8.5%)

    Тест 2 — Плоская пластина 0.5×0.2 м:
      Условия: α=5°, M=0.2, Re=10⁶
      Ожидаемый Cz: 0.548 ± 0.082 (ошибка ≤12%)

    Тест 3 — Цилиндр длиной 1 м, диаметром 0.1 м:
      Условия: β=90°, M=0.4
      Ожидаемый Cy: 1.2 ± 0.18 (ошибка ≤12.5%)

    Тест 4 — Типовая ракета (фюзеляж + 4 крыла):
      Условия: α=10°, M=1.5
      Ожидаемый Cz: 0.35 ± 0.05 (сравнение с экспериментом ЦАГИ,
      ошибка ≤14.3%)

    Тест 5 — Руль с отклонением 20°:
      Условия: M=0.8, δ=20°
      Ожидаемый ΔCz: 0.18 ± 0.03 (сравнение с DATCOM, ошибка ≤13%)

8.2. Тестирование граничных условий
    Должны быть проверены сценарии:
      • Старт с нулевой скорости (должно вызывать исключение при V<0.1 м/с)
      • Экстремальный манёвр с α=80° (должен расчитываться без исключения)
      • Штопор с α=86° (должно вызывать исключение)
      • Высота 100 км (ρ<0.01 — исключение)
      • Гиперзвук M=6.0 (исключение)


9. ИНТЕГРАЦИЯ В АРХИТЕКТУРУ IMODEL
───────────────────────────────────────────────────────────────────────────
9.1. Интерфейсный контракт
    Класс IAeroCalculator наследуется от базового интерфейса IModel
    существующей архитектуры симулятора. Все методы соответствуют
    требованиям к виртуальным деструкторам и константности.

9.2. Жизненный цикл
    • Создание: один экземпляр на каждый ЛА при инициализации сценария
    • Использование: вызов calculate() на каждом шаге интегрирования ОДУ
    • Уничтожение: автоматическая очистка ресурсов через деструктор (RAII)

9.3. Обработка ошибок в симуляторе
    Вызывающий код (ядро симулятора) обязан перехватывать исключения
    std::runtime_error от IAeroCalculator и:
      а) Логировать ошибку с указанием типа ЛА и условий полёта
      б) Прекращать симуляцию данного ЛА (не продолжать с нулевыми силами)
    Это обеспечивает детерминированное поведение при критических ошибках.


10. ЗАКЛЮЧЕНИЕ
───────────────────────────────────────────────────────────────────────────
Настоящее ТЗ полностью определяет требования к модулю аэродинамического
расчёта для военной симуляции. Все неопределённости устранены:

  ✓ Входные данные — вектор скорости вместо углов
  ✓ Референсные величины — только из метаданных STL
  ✓ Трение учитывается на всех поверхностях с числом Рейнольдса
  ✓ Интерференция — упрощённая модель площадей Прандтля
  ✓ Валидация — тип-зависимая с чёткими критериями
  ✓ Граничные условия — обработка через исключения
  ✓ Время расчёта — 150 мс с учётом трения
  ✓ Точность — ≤15% подтверждена верификационными тестами
  ✓ СК — правая связанная с осью Z вверх

ТЗ готово к передаче разработчику для реализации без дополнительных
уточнений.
